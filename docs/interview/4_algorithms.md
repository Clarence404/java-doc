## 一、复杂度

### Q1：大 O 表示什么？拿到一道题怎么根据数据规模反推该用什么复杂度？

**一句话**：大 O 描述的是数据量变大时耗时的增长趋势，只保留最高阶、忽略常数。按「1 秒大约 10⁸ 次简单运算」估算，就能从 n 的范围反推出能接受的算法。

| n 的规模 | 可接受的复杂度 | 常见做法 |
|----------|----------------|----------|
| ≤ 20 | O(2ⁿ) | 回溯、状态压缩 |
| ≤ 5000 | O(n²) | 双重循环、二维 DP |
| ≤ 10⁶ | O(n log n) | 排序、堆、二分 |
| ≤ 10⁸ | O(n) | 双指针、哈希、前缀和 |

- 增长顺序：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
- 空间复杂度同理，递归要算上调用栈的深度

→ 详见 [复杂度分析](/algorithms/0_complexity#一、时间复杂度)

### Q2：什么是均摊分析？为什么 `ArrayList.add` 是均摊 O(1)？

**一句话**：有些操作偶尔很贵、大多数时候很便宜，均摊分析把一串操作的总代价平摊到每一次上。`ArrayList` 扩容那次是 O(n)，但之后要再加约 n/2 个元素才会再扩容，平摊下来每次 O(1)。

- 扩容规则：容量不够时扩到约 1.5 倍并拷贝全部元素
- 同类例子：`HashMap.put` 的扩容、用两个栈实现队列、并查集（路径压缩 + 按秩合并后接近常数）
- 均摊 O(1) 不等于每次都快：单次请求不能卡顿的场景，应预估容量一次分配到位

→ 详见 [复杂度分析](/algorithms/0_complexity#三、均摊分析)

## 二、数组、链表、栈与队列

### Q3：数组和链表有什么区别？链表的插入删除真的是 O(1) 吗？

**一句话**：数组内存连续、随机访问 O(1)、缓存友好；链表靠指针串起来、随机访问 O(n)。链表插删 O(1) 有前提：**已经拿到了那个位置的节点**，先找位置仍然是 O(n)。

| 维度 | 数组 | 链表 |
|------|------|------|
| 随机访问 | O(1) | O(n) |
| 已知位置插删 | O(n)，要搬元素 | O(1)，只改指针 |
| 内存 | 连续，缓存友好 | 分散，每个节点多一到两个指针 |

- 实际工程里，即使有中间插删，`ArrayList` 往往也比 `LinkedList` 快，因为搬连续内存比追指针便宜
- 链表真正适合的是「手里已经有节点引用」的场景，比如 LRU 里把节点挪到表头

→ 详见 [数组与链表](/algorithms/1_data_structures/0_array_list#三、数组与链表对比)

### Q4：怎么判断链表有环？怎么找到环的入口？

**一句话**：快慢指针（Floyd 判圈）：慢指针一次走一步、快指针一次走两步，能相遇就有环；相遇后让一个指针回到表头，两个指针都一步一步走，再次相遇的位置就是入口。

- 原理：设表头到入口距离 a，相遇时快指针比慢指针多走了整数圈，推出 a 等于「相遇点再走若干圈回到入口」的距离
- 时间 O(n)，空间 O(1)；用 `HashSet` 记录走过的节点也能做，但空间是 O(n)
- 同一套快慢指针还能找链表中点、倒数第 N 个节点、两个链表的交点

→ 详见 [双指针](/algorithms/3_patterns/1_two_pointers#_2、找环的入口)

### Q5：Java 里实现栈和队列为什么推荐 `ArrayDeque`，而不是 `Stack` 或 `LinkedList`？

**一句话**：`Stack` 继承自 `Vector`，每个方法都加了锁，还暴露了按下标读写的方法，破坏了「只能动栈顶」的约束；`LinkedList` 每个节点都是一个对象，内存和缓存局部性都差。`ArrayDeque` 基于循环数组，又快又省。

- 栈用 `push` / `pop` / `peek`，队列用 `offer` / `poll` / `peek`，都是 `Deque` 接口的方法
- `Stack` 的 JDK 文档自己就建议改用 `Deque`

**常见坑**：`ArrayDeque` 不允许放 `null`；空栈时 `peek()` 返回 `null`，直接赋给 `int` 会拆箱 NPE，先判 `isEmpty()`。

→ 详见 [栈与队列](/algorithms/1_data_structures/1_stack_queue#_2、java-实现)

### Q6：单调栈解决什么问题？方向和 `>` / `>=` 怎么选？

**一句话**：单调栈专门解决「找左边或右边第一个比我大 / 小的元素」，每个元素只进出栈一次，O(n) 代替暴力的 O(n²)。

- 找右边第一个更大：栈内非递增，新元素大于栈顶就弹出，被弹出的元素答案就是新元素
- 找左边第一个更大：栈内严格递减，弹完之后的新栈顶就是答案
- `>` 还是 `>=` 决定相等元素去不去，也就是找「严格更大」还是「大于等于」；有重复值的题要想清楚
- 栈里通常存下标而不是值，方便算距离（每日温度）和宽度（柱状图最大矩形）

→ 详见 [栈与队列](/algorithms/1_data_structures/1_stack_queue#二、单调栈)

## 三、哈希表与堆

### Q7：哈希冲突有哪些解决方法？开放寻址法为什么不能直接删除元素？

**一句话**：两种主流做法：链地址法把冲突的元素挂成链表（或树），开放寻址法冲突时按规则往后找空槽。开放寻址查找时「遇到空槽就认为不存在」，直接清空会让后面的元素找不到。

| 方式 | 优点 | 缺点 | JDK 例子 |
|------|------|------|----------|
| 链地址法 | 简单，负载因子可以超过 1 | 每个节点多一个对象 | `HashMap`、`ConcurrentHashMap` |
| 开放寻址 | 数据都在一个数组里，缓存友好 | 负载因子必须小于 1，容易聚集 | `ThreadLocalMap`、`IdentityHashMap` |

- 开放寻址的删除：放一个「墓碑」标记，查找时跳过、插入时可以复用
- `HashMap` 的树化阈值、扩容迁移等细节见 Java 面试题

→ 详见 [哈希表](/algorithms/1_data_structures/2_hash_table#_2、哈希冲突的两种解法)

### Q8：如何手写一个 LRU 缓存？

**一句话**：哈希表 + 双向链表：哈希表负责 O(1) 找到节点，链表按访问顺序排列，访问时把节点挪到表头，满了就删表尾。Java 里最快的写法是继承 `LinkedHashMap`。

- `LinkedHashMap` 构造参数 `accessOrder=true` 按访问顺序排序，重写 `removeEldestEntry` 在超出容量时返回 true
- 手写时用哨兵头尾节点，省掉一堆判空；`get` 和 `put` 都要把节点移到表头
- 为什么要双向链表：删除节点需要拿到它的前驱，单链表做不到 O(1)

**常见坑**：这两种写法都不是线程安全的；生产环境的本地缓存直接用 Caffeine。

→ 详见 [哈希表](/algorithms/1_data_structures/2_hash_table#_3、linkedhashmap-实现-lru)

### Q9：堆是怎么实现的？为什么建堆是 O(n) 而不是 O(n log n)？

**一句话**：堆是一棵用数组存储的完全二叉树，下标 i 的子节点是 2i+1 和 2i+2。插入靠上浮、删堆顶靠下沉，都是 O(log n)；从最后一个非叶节点倒序下沉建堆只要 O(n)。

- 为什么是 O(n)：大部分节点在底层，下沉距离很短，高度为 h 的节点约有 n / 2^(h+1) 个，加起来收敛到 O(n)
- 逐个插入建堆才是 O(n log n)
- `PriorityQueue` 默认小顶堆；`remove(Object)` 是 O(n)，迭代顺序不是有序的

**常见坑**：大顶堆写成 `(a, b) -> b - a`。有溢出风险，用 `Comparator.reverseOrder()`。

→ 详见 [堆](/algorithms/1_data_structures/4_heap#二、核心操作)

### Q10：Top K 问题怎么做？堆和快速选择怎么选？

**一句话**：求最大的 K 个数，维护一个大小为 K 的**小顶堆**，比堆顶大就替换，O(n log K)；只要第 K 大且允许改原数组，用快速选择，平均 O(n)。

| 方法 | 时间 | 特点 |
|------|------|------|
| 小顶堆 | O(n log K) | 适合数据流、数据量大于内存，K 小时很省 |
| 快速选择 | 平均 O(n)，最坏 O(n²) | 要随机选基准，会修改数组 |
| 全排序 | O(n log n) | 最简单，n 小时没问题 |

- 数据流中位数：大顶堆存较小的一半、小顶堆存较大的一半，保持两边数量差不超过 1
- 海量数据的 Top K（分桶 + 多机合并）见业务场景面试题

→ 详见 [堆](/algorithms/1_data_structures/4_heap#五、top-k-问题)

## 四、树与图

### Q11：AVL 树和红黑树有什么区别？为什么 `TreeMap` 和 `HashMap` 用红黑树？

**一句话**：AVL 严格平衡（左右高度差不超过 1），查找略快但修改时调整多；红黑树只要求近似平衡（最长路径不超过最短路径的 2 倍），插入最多旋转 2 次、删除最多 3 次，读写均衡，所以通用库都选它。

| | AVL 树 | 红黑树 |
|--|--------|--------|
| 树高上界 | 约 1.44 log₂n | 2 log₂(n + 1) |
| 删除时旋转 | 最坏 O(log n) 次 | 至多 3 次 |
| 适用 | 查多改少 | 读写均衡，通用首选 |

- 红黑树新节点总是染红插入，只可能和红色父节点冲突，大部分修复只需要变色
- 应用：`TreeMap` / `TreeSet`、`HashMap` 桶内树化、Linux 调度器、Nginx 定时器

→ 详见 [树](/algorithms/1_data_structures/3_tree#_3、与-avl-对比)

### Q12：数据库索引为什么用 B+ 树？三层 B+ 树大约能存多少行？

**一句话**：磁盘按页读写，B+ 树一个节点就是一页，分叉多、树很矮，查一次只要两三次 IO；数据只放在叶子上，叶子用链表串起来，范围查询和排序很方便。

- 树矮：内部节点只存 key 和页指针，一页能放上千个分叉
- 范围查询：找到起点后沿叶子链表顺序读，不用回到上层
- 查询稳定：所有查询都走到叶子，耗时可预测
- 估算（BIGINT 主键、每行约 1 KB、页 16 KB）：每个内部页约 1170 个分叉，每个叶子页 16 行，三层约 1170 × 1170 × 16 ≈ 2190 万行；行越大能存的越少

→ 详见 [树](/algorithms/1_data_structures/3_tree#六、b-树-b-tree)

### Q13：图的最短路径算法怎么选？Dijkstra 为什么不能处理负权边？

**一句话**：无权图用 BFS，非负权图用 Dijkstra，有负权边用 Bellman-Ford，要任意两点距离且点少用 Floyd。Dijkstra 是贪心：每次取出的最近点就认为确定了，负权边可能让「已确定」的距离事后变小。

| 算法 | 负权边 | 时间复杂度 |
|------|--------|------------|
| BFS | 仅无权图 | O(V + E) |
| Dijkstra（堆优化） | 不支持 | O(E log V) |
| Bellman-Ford | 支持，能检测负环 | O(V × E) |
| Floyd-Warshall | 支持（不能有负环） | O(V³) |

- 堆优化的 Dijkstra 要跳过「过期」的堆元素：同一个点可能被多次入堆，弹出时距离已不是最新的就跳过
- Bellman-Ford 做完 V−1 轮松弛后，第 V 轮还能松弛就说明有负环

→ 详见 [图](/algorithms/1_data_structures/5_graph#六、最短路径)

### Q14：并查集是做什么的？路径压缩和按秩合并带来什么？

**一句话**：并查集处理「动态连通性」：不断合并集合，随时问两个元素是否在同一个集合里。路径压缩加按秩合并后，单次操作均摊接近常数（O(α(n))）。

- 结构：每个集合是一棵树，根节点代表整个集合，`find` 找根、`union` 把一棵树的根挂到另一棵下
- 路径压缩：`find` 时把沿途节点直接挂到根上，下次查找一步到位
- 按秩合并：矮树挂到高树下，避免树退化成链表
- 典型应用：朋友圈 / 岛屿数量、判断无向图有没有环、Kruskal 最小生成树

→ 详见 [图](/algorithms/1_data_structures/5_graph#七、并查集-union-find)

### Q15：字典树（Trie）和哈希表比有什么优势？适合什么场景？

**一句话**：哈希表能 O(L) 判断一个单词在不在，但回答不了「有哪些词以 `ap` 开头」；Trie 把公共前缀只存一份，前缀查询只要沿路径走 L 步。

- 结构：每条边一个字符，节点上的 `isEnd` 标记「到这里是一个完整的词」
- 场景：搜索框自动补全、敏感词过滤、IP 路由最长前缀匹配、二进制 Trie 求最大异或值
- 代价：节点多、内存大；字符集大时用 `Map` 存子节点，字符集小且固定时用数组
- 多模式匹配（敏感词）用 AC 自动机：在 Trie 上加失败指针，一次扫描匹配所有词

→ 详见 [字典树（Trie）](/algorithms/1_data_structures/6_trie#三、应用场景)

## 五、排序与查找

### Q16：常见排序算法的复杂度和稳定性？`Arrays.sort` 用的是什么？

**一句话**：O(n log n) 的三个主力是归并（稳定、要额外空间）、快排（平均最快、不稳定）、堆排（原地、不稳定）；JDK 对基本类型用双轴快排，对对象用 TimSort，因为对象排序需要稳定。

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
|------|------|------|------|------|
| 归并排序 | O(n log n) | O(n log n) | O(n) | 是 |
| 快速排序 | O(n log n) | O(n²) | O(log n) | 否 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 否 |
| 插入排序 | O(n²) | O(n²) | O(1) | 是 |

- 稳定：相等的元素排序后保持原来的相对顺序，多关键字排序时很关键
- 值域小的整数可以用计数排序，O(n + k)

**常见坑**：比较器写成 `(a, b) -> a - b`，相减溢出会导致排序结果错误，TimSort 还可能抛 `Comparison method violates its general contract!`。用 `Integer.compare` 或 `Comparator.comparingInt`。

→ 详见 [排序算法](/algorithms/2_algorithms/1_sort#一、复杂度总览)、[排序算法](/algorithms/2_algorithms/1_sort#四、内置排序的实现)

### Q17：快速排序什么时候会退化到 O(n²)？怎么避免？

**一句话**：每次选的基准都是当前区间的最大或最小值时，划分极度不平衡，就退化成 O(n²)，典型是固定选第一个元素、输入又已经有序。

- 随机选基准：让最坏情况几乎不可能出现
- 三数取中：取首、中、尾三个数的中位数作为基准
- 大量重复元素：扫描时遇到等于基准的值两边都停下交换，或者用三路快排把等于基准的放中间
- 递归过深时转堆排序（JDK 双轴快排就这么兜底），小区间改用插入排序

→ 详见 [排序算法](/algorithms/2_algorithms/1_sort#_6、快速排序)

### Q18：二分查找的边界怎么写不出错？什么是「二分答案」？

**一句话**：先选定一种区间写法（闭区间或左闭右开），再让循环条件和指针移动跟它严格匹配；二分的前提只是「单调性」，不一定是数组有序。

- 闭区间 `[lo, hi]`：`hi = n - 1`，`while (lo <= hi)`，`lo = mid + 1` / `hi = mid - 1`
- 左闭右开 `[lo, hi)`：`hi = n`，`while (lo < hi)`，`lo = mid + 1` / `hi = mid`；找左右边界时更顺手
- `mid` 写成 `lo + (hi - lo) / 2`，避免 `lo + hi` 溢出
- 二分答案：答案越宽松越容易满足时（如吃香蕉的最小速度），直接在答案范围上二分，每次用 O(n) 检查是否可行

→ 详见 [搜索算法](/algorithms/2_algorithms/0_search#一、二分查找)

## 六、算法思想

### Q19：分治、动态规划、贪心有什么区别？

**一句话**：三者都是把大问题拆成小问题。分治的子问题相互独立；动态规划的子问题大量重叠，要把结果存下来；贪心每一步只做当前最优的选择，不回头。

| | 分治 | 动态规划 | 贪心 |
|--|------|---------|------|
| 子问题 | 相互独立 | 大量重叠 | 每步只留一个 |
| 缓存结果 | 不需要 | 需要 | 不需要 |
| 典型例子 | 归并排序、快速幂 | 背包、编辑距离 | 区间调度、跳跃游戏 |

- 分治的复杂度用主定理算，例如归并排序 T(n) = 2T(n/2) + O(n) = O(n log n)
- 能用贪心的题一定也能用 DP，但贪心更快；关键是能否证明贪心是对的

→ 详见 [分治算法](/algorithms/2_algorithms/2_divide_conquer#四、分治、动态规划与贪心)

### Q20：动态规划的题怎么下手？记忆化搜索和递推有什么区别？

**一句话**：先确认有最优子结构和重叠子问题，再按「定义状态 → 初始化 → 状态转移 → 遍历顺序 → 返回结果」五步走，最关键的是把 `dp[i]` 的含义写清楚。

- 记忆化搜索：自顶向下，递归 + 缓存，只算用得到的状态，好想但有递归深度限制
- 递推：自底向上填表，没有递归开销，还能用滚动数组把空间从二维压到一维
- 常见模型：一维（爬楼梯、打家劫舍、最大子数组和）、二维（LCS、编辑距离）、背包、区间 DP
- 最长递增子序列有 O(n log n) 解法：维护「长度为 i 的递增子序列的最小结尾」数组，二分更新

**常见坑**：斐波那契这类题 `int` 很快溢出（第 47 项就超了），要用 `long` 或按题意取模。

→ 详见 [动态规划](/algorithms/2_algorithms/5_dynamic_programming#一、动态规划思想)

### Q21：0-1 背包和完全背包的循环顺序为什么不同？

**一句话**：压成一维后，0-1 背包每件物品只能选一次，容量要**从大到小**遍历，保证 `dp[j - w]` 还是上一件物品时的旧值；完全背包可以重复选，容量**从小到大**遍历，`dp[j - w]` 里可能已经包含了当前物品。

| | 0-1 背包 | 完全背包 |
|--|---------|---------|
| 每件物品 | 最多一次 | 无限次 |
| 容量循环 | 倒序 | 正序 |
| 典型题 | 分割等和子集（LC 416） | 零钱兑换（LC 322） |

- 求最小值的背包（如零钱兑换）初始值设成「不可达」，用 `amount + 1` 当无穷大，比 `Integer.MAX_VALUE` 安全，加 1 不会溢出

→ 详见 [动态规划](/algorithms/2_algorithms/5_dynamic_programming#六、背包问题)

### Q22：怎么判断一道题能不能用贪心？

**一句话**：先想一个贪心规则，拿几个小例子和边界例子去验证；能举出反例就改用动态规划，找不到反例再用交换论证说明它是对的。

- 反例：硬币面额 `{1, 3, 4}` 凑 6，贪心先拿 4 得到 3 枚，最优是 3 + 3 共 2 枚
- 交换论证：把最优解的第一步换成贪心的选择，结果不变差，就说明存在以贪心开头的最优解
- 区间调度（最多不重叠区间）要按**结束时间**排序；按开始时间或长度排序都能找到反例

→ 详见 [贪心算法](/algorithms/2_algorithms/4_greedy#四、怎么判断能不能用贪心)

### Q23：回溯算法的通用框架是什么？排列组合怎么去重和剪枝？

**一句话**：回溯就是在决策树上做 DFS：做选择 → 递归 → 撤销选择。排列、组合、子集的区别只在「下一层能选哪些元素」，去重统一用「先排序，同一层跳过相同的值」。

- 排列：用 `used[]` 标记已用的元素，每层都从头选
- 组合 / 子集：传 `start`，下一层只能选当前元素之后的；可重复选时递归传 `i` 而不是 `i + 1`
- 剪枝：排序后超过目标就停、剩余元素不够就停、只问存在性时找到一个就返回
- 复杂度 ≈ 决策树节点数 × 每个节点的工作量，全排列是 O(n · n!)

**常见坑**：收集结果时 `result.add(path)` 存的是同一个引用，回溯结束后会被撤销成空列表，要 `new ArrayList<>(path)`。

→ 详见 [回溯算法](/algorithms/2_algorithms/3_backtrack#三、排列、组合与子集)

## 七、常见技巧与刷题方法

### Q24：双指针和滑动窗口有什么区别？滑动窗口的适用前提是什么？

**一句话**：滑动窗口是同向双指针的一种：右指针扩张、左指针收缩，维护一段连续区间，每个元素最多进出窗口一次，O(n)。前提是窗口扩大时某个量单调变化，否则不知道什么时候该收缩左边界。

- 对撞指针：左右两端向中间走，用于有序数组的两数之和、三数之和、盛水最多的容器
- 快慢指针：链表判环、找中点、数组原地去重
- 滑动窗口：无重复字符的最长子串、最小覆盖子串、长度最小的子数组
- 数组里有负数时「和」不再单调，求和为 k 的子数组要改用前缀和 + 哈希表（见下一题）

→ 详见 [滑动窗口](/algorithms/3_patterns/2_sliding_window#一、核心思想与模板)、[双指针](/algorithms/3_patterns/1_two_pointers)

### Q25：前缀和与差分数组分别解决什么问题？有负数时怎么求和为 k 的子数组个数？

**一句话**：前缀和让「区间求和」变成 O(1)，差分数组让「区间整体加一个数」变成 O(1)；和为 k 的子数组用「前缀和 + 哈希表」，有没有负数都适用。

- 前缀和：`p[i+1] = p[i] + nums[i]`，区间 `[l, r]` 的和是 `p[r+1] - p[l]`；多开一位哨兵省掉边界判断
- 差分数组：区间 `[l, r]` 加 v 只改 `d[l] += v`、`d[r+1] -= v`，最后求一遍前缀和还原
- 和为 k：遍历时问「之前有多少个前缀和等于当前前缀和 − k」，哈希表要先放入 `{0: 1}` 表示空前缀

→ 详见 [前缀和与差分数组](/algorithms/3_patterns/3_prefix_sum#四、前缀和-哈希表)

### Q26：常用的位运算技巧有哪些？`>>` 和 `>>>` 有什么区别？

**一句话**：`n & (n - 1)` 消去最低位的 1，`n & -n` 取出最低位的 1，异或能让成对的数相互抵消；`>>` 是算术右移（补符号位），`>>>` 是逻辑右移（补 0）。

- `n & (n - 1) == 0` 判断 2 的幂；循环消 1 可以数二进制里有几个 1
- 异或：所有数异或一遍，出现两次的抵消，剩下只出现一次的数
- 状态压缩：用一个整数的每一位表示一个元素选没选，枚举子集 / 状压 DP，适合 n ≤ 20 左右

**常见坑**：`int` 的移位距离只取低 5 位，`1 << 32` 等于 1，要 32 位以上写 `1L << k`；`==` 优先级高于 `&`，`n & 1 == 0` 会编译失败，要加括号。

→ 详见 [位运算](/algorithms/3_patterns/4_bit_manipulation#二、常用技巧)

### Q27：算法题该怎么刷？机考的输入输出要注意什么？

**一句话**：按题型刷而不是按题号刷，每类先吃透一个模板再做变形；机考是 ACM 模式，要自己从标准输入读数据、往标准输出写结果。

- 刷题顺序：数组与双指针 → 链表 → 栈和队列 → 哈希 → 二叉树 → 二分 → 回溯 → 动态规划 → 图
- 每道题先根据数据规模估复杂度（见 Q1），写完用空输入、单元素、重复值、极值自测
- 输入：数据量小用 `Scanner`；数据多用 `BufferedReader` 按行读到 EOF，再 `trim().split("\\s+")` 拆分
- 输出：大量输出用 `StringBuilder` 或 `PrintWriter` 一次写出，最后记得 `flush`

→ 详见 [LeetCode 高频题分类](/algorithms/4_practice/0_leet_code)、[华为 OJ 题型与技巧](/algorithms/4_practice/1_huawei_oj#一、输入输出处理)
