接入层架构

本篇目标：理清一个请求从用户到应用要经过哪几层入口，每层负责什么、靠什么扛量，以及接入层自身如何做到不成为单点。

参考链接：LVS 官方文档 · Nginx 官方文档 · Nginx Ingress

接入层是高并发的第一道闸门：越靠前的层级单位请求成本越低，能在前面挡住或消化的流量，就不要放到后面。一个典型的请求入口从外到内依次是 DNS / GSLB → CDN → 四层负载均衡 → 七层网关 → 应用集群。

一、入口分层总览

每一层都在"分发"和"过滤"两件事上做取舍：前面的层看到的信息少（只有 IP、端口），但吞吐高；后面的层能理解 HTTP 语义，但单机处理能力低。

层级职责扛量手段典型组件
DNS / GSLB把用户导向就近、健康的机房入口按地域 / 运营商调度；多入口 IP 分摊智能 DNS、云解析、HTTPDNS
CDN在边缘节点缓存可公开的内容静态资源与静态化页面就近命中，只回源未命中部分云 CDN、Cloudflare
四层负载均衡按 IP + 端口转发 TCP / UDP 连接内核态转发，不解析应用层协议，单机可承载海量连接LVS、云 SLB / NLB、HAProxy（TCP 模式）
七层网关理解 HTTP，做路由、TLS 卸载、鉴权、限流多实例水平扩展，前置四层负载均衡Nginx、OpenResty、Ingress、Spring Cloud Gateway
应用集群执行业务逻辑无状态化 + 水平扩展Spring Boot 服务

负载均衡算法、健康检查与会话保持见 负载均衡；本篇只讲各层在"扛量"上的定位。

二、DNS 与全局调度

DNS 是最便宜的分流手段，但生效慢、不可控：解析结果会被运营商 Local DNS 和客户端缓存，改记录后要等缓存过期才全部生效。

手段作用注意点
智能解析按用户所在地域、运营商返回不同机房的入口 IP依赖 Local DNS 的出口 IP 判断用户位置，可能不准
GSLB（全局负载均衡）在 DNS 基础上加入机房健康探测与容量权重机房故障时摘除其 IP，但受缓存影响切换需要分钟级
多 A 记录一个域名返回多个入口 IP，客户端自行选择没有健康检查，某个 IP 挂了部分用户仍会访问到
HTTPDNSApp 通过 HTTP 接口直接向调度服务要 IP绕过 Local DNS 劫持和缓存，调度更精确，只适用于 App

设置建议

入口域名的 TTL 设为 60 ~ 300 秒，兼顾切换速度与解析压力；DNS 只负责机房级粗调度，机房内的精细分发交给负载均衡。

三、CDN 与动静分离

CDN 把可公开、可缓存的内容推到离用户最近的节点，源站只处理未命中和动态请求。对于图片、JS/CSS、视频这类流量，CDN 能消化绝大部分带宽。

1、动静分离

先把请求分成两类，再分别走不同的链路：

类型内容链路缓存策略
静态资源JS、CSS、图片、字体、视频独立域名 → CDN → 对象存储文件名带内容哈希，Cache-Control: max-age 设为长期
静态化页面商品详情、活动页、文章页CDN → Nginx → 页面文件短 TTL + 变更时主动刷新
动态请求下单、支付、个人数据绕过 CDN 或只做加速回源不缓存

静态资源用独立域名还有一个好处：请求不带主站 Cookie，减少上行流量。

2、页面静态化

把"每次请求都查库渲染"的页面，变成"数据变更时生成一次、之后直接读文件"。适合读多写少、千人一面的页面。

方式做法适用场景
全量静态化数据变更时用模板引擎生成完整 HTML，推送到 Nginx / 对象存储文章、帮助中心、活动落地页
页面片段化页面主体静态化，价格、库存、登录态等个性化部分由前端异步请求接口商品详情页、秒杀页
边缘渲染CDN 边缘节点用 ESI 或边缘函数拼装片段大规模电商、门户

静态化的一致性

静态页一旦推到 CDN，失效要靠 TTL 或主动刷新（通常分钟级生效）。价格、库存这类强一致数据不要写死在静态页里，放到异步接口中单独获取。

3、回源保护

CDN 节点未命中或内容过期时会回源，大量节点同时回源可能反过来冲垮源站：

  • 开启 CDN 的回源合并（同一资源并发未命中只回源一次）或中间层缓存
  • 大促前对热门资源做 CDN 预热，而不是等首个请求触发回源
  • 源站前的 Nginx 配置 proxy_cache 作为二级缓存

多级缓存的整体设计见 缓存架构设计。

四、四层与七层负载均衡

四层负责"扛连接"，七层负责"懂业务"，生产环境通常组合使用：四层做入口 VIP，后面挂多台七层网关。

1、四层：LVS / 云 SLB

LVS 工作在内核 IPVS 模块，只看 IP 和端口，转发开销极低。常见转发模式：

模式原理优点限制
NAT改写目标 IP，请求与响应都经过 LVS配置简单，后端无需特殊设置响应流量也经过 LVS，易成瓶颈
DR只改写 MAC 地址，响应由后端直接返回客户端性能最好，LVS 只承担入向流量后端与 LVS 需在同一二层网络，后端需在 lo 上配置 VIP
TUNIP 隧道封装转发，响应直接返回可跨网段后端需支持 IP 隧道
FULLNAT同时改写源和目标地址可跨 VLAN 部署，运维灵活后端看不到客户端 IP，需 TOA 等模块透传

公有云上一般直接使用云 SLB / NLB，由云厂商负责集群化和跨可用区容灾。

2、七层：Nginx / API 网关

七层网关能解析 HTTP，承担路由、TLS 卸载、鉴权、限流、灰度等职责。扛量的关键配置：

worker_processes auto;                 # 与 CPU 核数一致
events {
    worker_connections 65535;          # 单 worker 最大连接数，受 ulimit -n 约束
}
http {
    upstream order_service {
        server 10.0.1.11:8080;
        server 10.0.1.12:8080;
        keepalive 64;                  # 与后端保持的空闲长连接数，避免每个请求都新建 TCP
    }
    server {
        location /api/order/ {
            proxy_pass http://order_service;
            proxy_http_version 1.1;    # 复用上游长连接必须用 HTTP/1.1
            proxy_set_header Connection "";
            proxy_connect_timeout 1s;
            proxy_read_timeout 3s;     # 上游超时要短于客户端超时
        }
    }
}

注意点：

  • 网关要保持无状态，才能在四层负载均衡后面水平扩展
  • 网关只做通用横切逻辑，不写业务逻辑，否则每次业务变更都要改网关
  • Spring Cloud Gateway 的路由与过滤器配置见 API 网关

五、TLS 卸载

TLS 握手（尤其是非对称加密部分）是入口层最主要的 CPU 开销之一，通常在最外层的负载均衡或 Nginx 上统一完成，内部转发走 HTTP 或内网 mTLS。

手段作用
在 SLB / Nginx 集中卸载证书集中管理，后端应用不再处理加解密
会话复用（Session Cache / Session Ticket）客户端重连时跳过完整握手
启用 TLS 1.3完整握手只需 1-RTT
使用 ECDSA 证书签名运算比同等安全强度的 RSA 更省 CPU
OCSP Stapling由服务端附带证书状态，客户端无需单独查询

卸载之后内网是明文，是否需要内部加密取决于安全要求，零信任架构下服务间通常改用 mTLS，见 零信任。TLS 协议细节见 HTTPS 与 TLS。

六、长连接接入

IM、推送、IoT 等场景的压力不在 QPS，而在同时在线的连接数：每条连接都占用文件描述符、内存和心跳处理开销，应与短连接业务分开部署。

要点做法
独立长连接网关WebSocket / MQTT 网关只管连接、编解码和心跳，业务逻辑通过 RPC / MQ 交给后端服务
连接路由表在 Redis 记录 userId → 网关节点，下行消息先查路由，再投递到持有连接的节点
四层负载均衡长连接走 LVS / SLB 的 TCP 转发，按连接数而不是请求数均衡
空闲超时对齐负载均衡的空闲超时必须大于客户端心跳间隔，否则连接会被中间设备静默断开
防重连风暴网关重启或机房切换时，客户端重连采用指数退避 + 随机抖动
系统参数调大 ulimit -n、somaxconn 等，见 并发参数调优

基于 Netty 的长连接网关实现（心跳、WebSocket、生产调优）见 Netty 总览；MQTT 等物联网协议见 通信协议。

七、接入层限流与防刷

接入层限流的定位是"挡住明显超出容量或明显异常的流量"，越早拦截，后端资源浪费越少；精细的业务级限流仍在网关和应用层完成。

层级拦截对象典型手段
CDN / WAFCC 攻击、爬虫、恶意 IP频率规则、IP 信誉库、人机校验
Nginx单 IP 请求过多limit_req / limit_conn
API 网关单用户、单接口超限按用户 / 接口维度的令牌桶，分布式计数
应用服务整体过载Sentinel 等自适应保护

Nginx 按 IP 限流的最小示例：

# 每个 IP 每秒 10 个请求，状态保存在 10MB 共享内存中
limit_req_zone $binary_remote_addr zone=per_ip:10m rate=10r/s;

server {
    location /api/ {
        limit_req zone=per_ip burst=20 nodelay;   # 允许 20 个突发，超出直接返回
        limit_req_status 429;
        proxy_pass http://backend;
    }
}

注意客户端真实 IP

Nginx 前面有 SLB 或 CDN 时，$binary_remote_addr 是上一跳的地址，需要用 real_ip 模块从可信代理的 X-Forwarded-For 中取真实 IP，否则会把整个 CDN 节点当成一个用户限流。

限流算法、分层限流设计与过载保护见 限流与过载保护；接口签名、防重放见 API 安全。

八、接入层自身的高可用

接入层是所有流量的必经之路，任何一层是单点，整个系统就是单点：

层级高可用手段
DNS使用多家 DNS 服务商或云解析的多线路容灾；GSLB 探测机房健康
CDN天然多节点；源站配置多个回源地址
四层负载均衡自建 LVS 用 Keepalived（VRRP）主备漂移 VIP；云 SLB 选择多可用区实例
七层网关多实例部署在不同可用区，由四层负载均衡做健康检查与摘除
跨机房各机房独立入口，GSLB 在机房故障时切换解析

Keepalived VIP 配置与故障切换流程见 冗余与故障转移，机房级容灾见 多活与容灾。

小结

  • 请求入口按 DNS / GSLB → CDN → 四层 → 七层 → 应用分层，越靠前越便宜，能前置消化的流量不要放到后面
  • 动静分离 + 页面静态化让读流量在 CDN 和 Nginx 消化，强一致数据走异步接口单独获取
  • 四层扛连接、七层懂业务，TLS 在入口集中卸载并开启会话复用
  • 长连接业务独立部署网关，重点关注连接数、心跳与重连风暴
  • 接入层限流只挡明显超量和异常的流量，每一层都要有冗余，不能成为单点
