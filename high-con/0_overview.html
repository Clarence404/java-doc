高并发总览

高并发系统设计的目标是流量变大时系统依然扛得住，并且流量翻倍时能靠加机器线性提升容量。本模块讲接入层、水平扩展、缓存、削峰、数据层扩展、热点与容量规划。

版本基线（2026 年 10 月）：JDK 21、Spring Boot 4、Redis 8.x、RocketMQ 5.x、MySQL 8.4

一、核心要点

高并发关注的是"规模"：请求量从 1k QPS 涨到 10w QPS 时，瓶颈在哪里、如何扩展、如何削峰、如何应对热点。单次请求快不快是高性能的问题，故障时停不停服是高可用的问题。

高并发设计的基本思路可归纳为四句话：

思路含义典型手段
能扩任何一层都能通过加机器提升容量无状态化、负载均衡、分库分表
少打让请求尽量不落到最慢、最贵的那一层CDN、页面静态化、多级缓存
慢做非核心、可延迟的工作不在请求链路上同步完成MQ 异步、削峰填谷、排队
分散避免流量集中到单点、单 key、单行热点打散、分桶、请求合并

四、推荐阅读路径

按请求从外到内的路径阅读：入口 → 扩展 → 缓存 → 异步 → 数据 → 热点 → 调优 → 容量。

阶段要解决的问题文章
入口与扩展请求怎么进来、应用层怎么靠加机器扛量？接入层架构 → 水平扩展与无状态化
读写分流读流量怎么挡在数据库之前、写洪峰怎么摊平？缓存架构设计 → 异步与削峰
存储与热点数据库怎么扩展、流量集中到单点怎么办？数据层扩展 → 热点问题
调优与容量参数怎么配、要多少机器、怎么持续监控水位？并发参数调优 → 容量评估与规划

容量估算也是设计的起点

阅读顺序上容量规划放在最后，但做新系统设计时应先估算流量（日活 → 平均 QPS → 峰值 QPS → 存储量），再据此决定需要哪些手段。估算方法见 容量评估与规划。

五、服务监控

监控是扩容、调优和容量规划的依据：QPS、延迟分位数、错误率、线程池与连接池、下游 RT 等关键指标及水位告警阈值，统一见 容量评估与规划，完整可观测性方案见 可观测性。

六、与高性能、高可用的关系

"三高"是同一系统的三个观察角度，手段有交叉，但关注点不同：

模块核心问题衡量指标典型手段
高性能单次请求如何更快、更省资源RT、P99、CPU / 内存占用算法与数据结构、池化、异步与批量、JVM 调优、SQL 优化
高并发流量大时系统如何扛得住峰值 QPS、并发数、水位接入分层、水平扩展、缓存、削峰、分片、热点治理
高可用出故障时如何不停服可用性 SLA、MTTR冗余、限流、熔断、降级、隔离、故障转移
  • 高性能是高并发的基础：单机 RT 从 100ms 降到 20ms，同样的线程数可承载 5 倍 QPS（Little 定律 并发数 = QPS × RT，推导见 性能指标）
  • 高可用是高并发的底线：流量超过容量时，靠限流、降级保住核心链路，而不是整体雪崩；限流在入口与网关的分层设计见 限流与过载保护
  • 同一手段往往兼顾多个目标：缓存既降低 RT（高性能）又分担 DB 流量（高并发），多副本既扩展读能力（高并发）又提供故障转移（高可用）
  • 写流量的放大问题（一条动态推给百万粉丝的读写扩散取舍）见 Feed 流和消息推送
